# alexaroffCoachChess

macOS chess **Coach** (trainer) that sits on top of a real board on the screen.  
Primary target: **Duolingo Chess**.

## Current Goal

Give accurate move arrows in a real game:
- Player always sits at the bottom
- Can play as White or Black
- System must correctly understand whose turn it is
- Stockfish (~3000 Elo) is used only as the source of strong moves

Auto-play mode exists in the code but is **not** the priority right now.

---

## Project Status (26 July 2026)

### What is already done

- Full working prototype with screen capture, region selection, orientation lock, Stockfish, overlay arrows, and hybrid reconcile logic.
- Template-matching approach was thoroughly tested and **abandoned** — it cannot reliably track the position after a few moves on Duolingo’s styled board.
- Decision made: move to a **neural network** piece classifier (Variant A).

### Dataset

Synthetic dataset has been generated from clean Duolingo piece templates:

```
dataset/
  wP/ wN/ wB/ wR/ wQ/ wK/
  bP/ bN/ bB/ bR/ bQ/ bK/
  empty/
```

- Total: **4600 images** (350 per piece + 400 empty)
- Location: `dataset/` in the project root
- Generated by: `generate_synthetic_dataset.py`

### Training pipeline (ready)

Script: `train_piece_classifier.py`

It does two stages:

1. **Teacher** — MobileNetV3-Small fine-tuned on the synthetic dataset
2. **Student** — very small custom CNN trained with knowledge distillation from the teacher

Expected outputs after running the script:

```
models/
  teacher_mobilenet_v3_small.pt
  student_tiny_cnn.pt
  class_names.json
```

### Next concrete steps

1. Run the training:
   ```bash
   pip install torch torchvision
   python train_piece_classifier.py
   ```
2. Check validation accuracy of both teacher and student.
3. Integrate the best model (most likely the student) into `board_detector.py`, replacing the old template-matching logic.
4. Test on real Duolingo games (both as White and as Black).
5. Collect a small set of real screenshots to fine-tune further if needed.

## Important Design Decisions

- Player is always at the bottom of the board.
- When playing as Black, the opponent (White) moves first — the system must detect that move and only then suggest a reply.
- Vision quality is the current bottleneck, not Stockfish strength.
- We prefer a tiny fast model (distilled CNN) for real-time use on MacBook Air M2 8 GB.
